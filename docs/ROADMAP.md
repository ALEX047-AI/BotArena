## 3. Границы первой версии и дальнейшее развитие

| Входит в BotArena v0.1 (проектируется) | Не входит в BotArena v0.1 |
|---|---|
| Арена 12×12; стены; 10 ресурсов | 3D-мир и реалистичная физика |
| Два автономных бота | Сетевая игра и онлайн-сервер |
| Пошаговые раунды, очки, победа | Оружие, боевые эффекты, строительство баз |
| Random, Greedy, A* | Обучение нейросетей, RL |
| Локальный запуск матча и Pygame | Исполнение недоверенных скриптов в песочнице |
| JSON-протокол матча; CSV для серии | Облачная база данных, платные API |
| Тесты и сравнительный эксперимент | Полноценный редактор Python-кода внутри игры |

После подтверждения MVP можно расширить проект: новые стратегии, несколько режимов турниров, карты произвольного размера, визуальные редакторы, командные матчи и обучение агентов. Эти функции составляют перспективный план и **не считаются реализованными**.

При сокращении сроков сохраняются игровое ядро, две стратегии и проверяемый матч. Визуализация и третья стратегия добавляются после устойчивой работы логики. Такой порядок исключает ситуацию, когда красивая оболочка скрывает ошибочный движок.

**Статусы:** `ПЛАН` — нет проверяемого результата; `В РАБОТЕ` — выполняется; `ГОТОВО` — есть подтверждение тестом/демо; `ЗАБЛОКИРОВАНО` — указана причина. Проценты готовности без методики и проверяемых артефактов не используются.



## 20. Открытые вопросы и порядок изменения спецификации

- Уточнить минимальную поддерживаемую версию Python и версию Pygame после первого успешного запуска.
- Проверить соответствие генератора карт требованиям достижимости на всех исследовательских seed.
- Определить стандарт логирования ошибок пользовательских контроллеров и формат экспорта.
- Проверить реальные сроки конференции и допустимость помощи наставника.
- Утвердить условия лицензирования и публикации стабильного кода.

Каждое изменение правил фиксируется в журнале решений, обновляет спецификацию и связанные тесты. Отчёты экспериментов всегда привязаны к версии правил, при которой были получены.
