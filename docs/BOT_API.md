# API программируемого бота

**Проект:** BotArena. **Дата:** 19.11.2026. **Статус:** проектное требование, если не указано иное.

Контракт предназначен для доверенных локальных Python-модулей; это описание проектируемого интерфейса, а не документация к опубликованной библиотеке.


## 7. Контракт программируемого бота

Интерфейс разделяет **наблюдение** (`Observation`) и **действие** (`Action`). Контроллер получает только доступные по правилам данные и возвращает одну из пяти команд. Непосредственно изменять объекты игрового состояния контроллер не вправе.

Планируемое логическое описание вызова:

```python
# Иллюстрация контракта; не подтверждение существования модуля.
def decide(observation: Observation) -> Action:
    ...
```

Минимальное наблюдение содержит `round_index`, `max_rounds`, `arena_width`, `arena_height`, координаты стен и ресурсов, координаты своего и второго бота, очки обоих участников, идентификатор активного бота. Для MVP действует **полная наблюдаемость**: положение ресурсов и соперника видно целиком. Концепция ограниченного радиуса обзора отложена.

Планируемый пример структуры данных:

```json
{
  "round_index": 12,
  "max_rounds": 100,
  "self_id": "A",
  "self_position": [2, 3],
  "opponent_position": [8, 7],
  "scores": {"A": 3, "B": 2},
  "arena_size": [12, 12],
  "walls": [[4, 4], [4, 5]],
  "resources": [[1, 8], [9, 2]]
}
```

Это **проектный пример**, а не зафиксированный формат готового файла. Python-API должен использовать типизированные внутренние модели и передавать боту копию или неизменяемое представление наблюдения.

Ошибки стратегии не должны повреждать состояние матча: движок перехватывает исключение, регистрирует тип ошибки и применяет оговорённую политику `WAIT` с записью `BOT_ERROR`. Время исполнения контроллера в MVP учитывается диагностически; полноценные квоты CPU/памяти относятся к следующему этапу. В первой версии подключаются только доверенные локальные модули, а не произвольный код от сторонних пользователей.



## 8. Эталонные стратегии

**Random.** Равновероятно выбирает допустимое действие перемещения среди возможных направлений; если движения нет, возвращает `WAIT`. Использует выделенный генератор случайных чисел с указанным seed. Это контрольный базовый алгоритм.

**Greedy.** Ищет ближайший ресурс по расстоянию Манхэттена и выбирает соседний допустимый шаг, уменьшающий это расстояние. При равенстве применяется устойчивый порядок направлений, прописанный в реализации и журнале. Жадная стратегия не исследует всю карту: она может застревать в локально неудачных решениях из-за стены или тупика.

**A*.** Рассматривает свободные клетки как граф с рёбрами между соседними клетками и весом 1; для выбора ресурса строит кратчайший путь алгоритмом A* с эвристикой Манхэттена, допустимой на такой сетке. При нескольких ресурсах выбирает достижимую цель с минимальной длиной найденного пути. Занятая соперником клетка считается временно недоступной; при изменении расположения противника маршрут пересчитывается. Если доступных ресурсов нет, возвращает `WAIT`.

Для каждой стратегии фиксируются версия алгоритма и параметры. Корректность A* проверяется относительно BFS на небольших эталонных картах. Условия сравнения не должны давать одному контроллеру дополнительную информацию или больше игровых действий.



## 10. Модели данных, события и воспроизводимость

| Сущность | Существенные поля |
|---|---|
| `ArenaConfig` | width, height, map_seed, obstacle_density, resource_count |
| `ArenaState` | walls, remaining_resources, starts, map_id |
| `BotState` | id, position, score, strategy_id |
| `GameState` | arena, bots, round_index, turn_order, status |
| `Observation` | read-only state visible to a bot |
| `GameEvent` | round, actor, requested_action, applied_action, position_before/after, outcome |
| `MatchResult` | winner, final_scores, rounds_played, map_id, seed, versions, errors |
| `ExperimentRun` | dataset_id, strategy_pair, side_assignment, config, result_path |

Журнал событий фиксирует входную конфигурацию, версии правил и алгоритмов, действия, начисления очков, ошибки контроллеров и причину завершения матча. Для последующего воспроизведения необходимы карта/seed, порядок ходов, версии стратегий и их собственные случайные зерна.

**Формат результатов:** JSON для полного отдельного матча и CSV для сводной таблицы по серии. Поля, сериализация и точные имена файлов уточняются при разработке, после чего фиксируются в схеме с версией (`schema_version`). Протокол не содержит ключей доступа и пользовательских секретов.

Одинаковый `map_seed` гарантирует сравнимую карту только при неизменной версии генератора и алгоритма случайных чисел. Поэтому для серьёзного эксперимента дополнительно сохраняется фактическое поле и его контрольная сумма.

## Дополнение от 26.11.2026 — фактический Python-API

Сейчас контроллер — **доверенный локальный объект**, имеющий метод `decide(observation)`. Он должен вернуть один из `Action.UP`, `Action.DOWN`, `Action.LEFT`, `Action.RIGHT`, `Action.WAIT` или соответствующую строку. Импорт: `from botarena.core.models import Action, Observation`. Снимок `Observation` содержит `round_index`, `max_rounds`, `self_id`, `self_position`, `opponent_position`, `score_a`, `score_b`, `width`, `height`, `walls` (`frozenset`) и `resources` (`frozenset`). Есть метод `legal_moves()` — доступные направления и координаты. Свойство `scores` возвращает копию словаря.

Пример вызова **из доверенного кода**, а не загрузки произвольного файла:

```python
from botarena.core.models import Action

class WaitBot:
    def decide(self, observation):
        return Action.WAIT
```

Движок отлавливает обычные исключения контроллера как `BOT_ERROR`, превращая его ход в `WAIT`. Ошибки команды и столкновения записываются как `INVALID_ACTION`. Полноценной песочницы для непроверенного Python-кода **нет** — запуск чужих скриптов небезопасен.
