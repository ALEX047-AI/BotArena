Для каждого теста в отчёте фиксируются версия программы, исходные данные, ожидаемый результат, фактический результат и статус. Наличие плана BA-01…BA-22 **не означает, что тесты уже созданы или прошли**. После реализации должны появиться реальные автоматические тесты и протокол их выполнения.

Критерии минимально готовой версии: демонстрируемый матч из двух ботов; счёт и завершение по правилам; три стратегии; повторяемый запуск; работающий графический интерфейс; сохранённый результат; отсутствие критических ошибок в ключевых тестах. Исследовательские выводы публикуются только после запусков.



## 15. Надёжность, безопасность и ограничения

**Изоляция:** до реализации отдельной безопасной среды исполнения BotArena загружает только доверенные локальные Python-модули проекта. Публичное API написания стратегий не означает, что можно безопасно выполнять любой присланный `.py`-файл. Подключение внешних пользовательских ботов потребует изоляции процессов, ограничений ресурсов, файлового доступа и проверки угроз.

**Целостность:** стратегия не изменяет игровое состояние в обход движка; любые полученные команды валидируются. При сбое контроллера журнал фиксирует ошибку, а матч не должен повреждать исходную карту.

**Воспроизводимость:** версии правил и алгоритмов, seed, карта и входные параметры фиксируются. Порядок действий определяется документированным циклом, не частотой обновления графики.

**Ограничения модели:** клеточная карта упрощает реальную робототехнику; препятствия статичны; датчики идеализированы; полноценной физики движения нет; агенты в MVP не обучаются на опыте. Перенос выводов на реальных роботов без дополнительных исследований не допускается.

**Конфиденциальность:** API-ключи, токены, `.env`, личные сведения и внутренние рабочие заметки не помещаются в публичный репозиторий; закрытый репозиторий также не считается безопасным местом для секретов.

## Реальная проверка на 26.11.2026

В комплекте есть **33 автоматических теста** (файлы `tests/test_arena.py`, `test_engine.py`, `test_strategies.py`, `test_storage_batch.py`), они прошли под Python 3.13.5. Проверены базовые состояния и ошибки арены, движение, счёт, раунды, последовательный порядок, стратегии, A* против BFS на контрольных случаях, сохранение JSON, пакет CSV, перестановка сторон. Наличие 33 тестов **не равняется** закрытию всех 22 сценариев BA-01…BA-22: каждый официальный сценарий требует отдельной записи о проверке по утверждённой методике и, для GUI, будущей реализации Pygame.

Файл [технического прогона](../research/SMOKE_RUN_2026-11-26.md) фиксирует также 540 выполненных headless-матчей; это проверка движка, не итог конференционного исследования. Испытания на Windows ещё предстоят.
