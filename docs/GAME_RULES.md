# Спецификация правил матча BotArena v0.1

**Проект:** BotArena. **Дата:** 19.11.2026. **Статус:** проектное требование, если не указано иное.

Один и тот же набор правил используется интерфейсом, игровым движком, тестами и исследовательским протоколом.


## 5. Правила игрового процесса v0.1

| Параметр | Проектное значение |
|---|---|
| Размер поля | 12 столбцов × 12 строк |
| Количество ботов | 2 (`A`, `B`) |
| Статические ресурсы | 10 штук; каждый приносит 1 очко |
| Длительность | Не более 100 раундов |
| Начальные очки | 0 у каждого |
| Допустимые действия | `UP`, `DOWN`, `LEFT`, `RIGHT`, `WAIT` |
| Перемещение | На одну клетку по вертикали или горизонтали |
| Сбор ресурса | Автоматически при входе на клетку с ресурсом |
| Ограничения | Нельзя выйти за границу, пройти стену или занять клетку другого бота |
| Конец матча | Собраны все ресурсы или прошёл 100-й раунд |
| Победа | Больше очков; при равенстве — ничья |

**Раунд** — возможность каждого бота выбрать ровно одно действие. Для MVP используется последовательное разрешение действий: в чётных раундах первым действует A, в нечётных — B. Второй бот получает обновлённое состояние. Это не одновременная механика; порядок хода записывается в журнал и учитывается при анализе. В исследованиях стороны и порядок стартовых условий меняются местами.

**Недопустимое действие** (столкновение, неизвестная команда, неправильный тип) не изменяет позицию бота, фиксируется как `INVALID_ACTION` и тратит текущий ход. Отсутствие ресурса под ботом не даёт очков. Команда `WAIT` допустима и также расходует ход. При одинаковых координатах на одном поле всегда может находиться не более одного бота.

Начальные позиции двух ботов различаются; обе клетки свободны. На них нет ресурса. Стены и ресурсы после начала матча неподвижны. Респавна ресурсов в MVP нет. Случайность при построении карты и в Random-стратегии управляется независимыми фиксируемыми зернами.

Правила относятся к предлагаемой реализации v0.1 и могут изменяться только через запись нового решения и обновление тестов, чтобы результаты старых экспериментов оставались интерпретируемыми.



## 6. Генерация и проверка карты

Координаты задаются целочисленной парой `(x, y)` с началом `(0, 0)` в левом верхнем углу; x растёт вправо, y — вниз. Допустимые значения — от 0 до 11 включительно. Стена не может совпадать с ресурсом или стартовой точкой.

В первой версии предлагается генератор с параметрами `map_seed`, `obstacle_density`, `resource_count=10`. Для исследования используются три уровня плотности препятствий: **10%, 20% и 30%** от 144 клеток. Фактическое число стен сохраняется в результате, поскольку округление долей даёт разные целые количества.

Генератор сначала резервирует две стартовые клетки, затем формирует стены и проверяет доступность карты. Для корректного сравнения каждый ресурс должен быть достижим из обеих начальных позиций по свободным клеткам в статической карте. Если условие не выполняется, генератор повторяет построение в рамках фиксированной воспроизводимой процедуры или отклоняет конфигурацию с понятной диагностикой. Карты и ресурсы должны сохраняться вместе с идентификатором или контрольной суммой.

Тестовые карты должны содержать также искусственные случаи: узкие коридоры, тупики, пустое поле, недостижимая цель и блокировка допустимого хода. Недостижимые ресурсы не должны попадать в основную исследовательскую выборку, но нужны для модульных тестов корректной обработки ошибок.



## 8. Эталонные стратегии

**Random.** Равновероятно выбирает допустимое действие перемещения среди возможных направлений; если движения нет, возвращает `WAIT`. Использует выделенный генератор случайных чисел с указанным seed. Это контрольный базовый алгоритм.

**Greedy.** Ищет ближайший ресурс по расстоянию Манхэттена и выбирает соседний допустимый шаг, уменьшающий это расстояние. При равенстве применяется устойчивый порядок направлений, прописанный в реализации и журнале. Жадная стратегия не исследует всю карту: она может застревать в локально неудачных решениях из-за стены или тупика.

**A*.** Рассматривает свободные клетки как граф с рёбрами между соседними клетками и весом 1; для выбора ресурса строит кратчайший путь алгоритмом A* с эвристикой Манхэттена, допустимой на такой сетке. При нескольких ресурсах выбирает достижимую цель с минимальной длиной найденного пути. Занятая соперником клетка считается временно недоступной; при изменении расположения противника маршрут пересчитывается. Если доступных ресурсов нет, возвращает `WAIT`.

Для каждой стратегии фиксируются версия алгоритма и параметры. Корректность A* проверяется относительно BFS на небольших эталонных картах. Условия сравнения не должны давать одному контроллеру дополнительную информацию или больше игровых действий.
